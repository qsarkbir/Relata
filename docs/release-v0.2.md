## 性能（NFR-03〜05）

2026-11-23、この環境（Linux、4 CPU、Chromium headless、`playwright.performance.config.ts`）で測定。条件は [v0.1 の公開前チェック](release-v0.1.md) と同じ（固定配置、選択中のみラベル）。

| 測定 | 結果 | 目標 |
|---|---|---|
| NFR-04: 1000 ノード・5000 エッジ、フィルタの再描画 | 255 ms | 達成 |
| NFR-04: 同、指標の完了（debounce を含む） | 1,652 ms | 達成 |
| NFR-03/05: 2000 ノード・8000 エッジのパン | 59.7 fps | 達成 |
| NFR-03/05: 5000 ノード・20000 エッジのパン | 49.0 fps | 参考（目標の対象外） |

時間の再生（T2-06）中の 2000 ノードでのフレーム数は測っていない。薄くする集合が変わったときだけ図を描き直す作りにしてある（設計書 §9.2）。

## ブラウザ（NFR-06）

- v0.2 の自動テストは Chromium だけで行った。この環境では Firefox と WebKit を入手できなかった（ダウンロードが失敗する）。v0.1 の時点では Chrome、Edge、Firefox、WebKit の各 91 件が成功している。
- 手元で確かめるときは、v0.1 の公開前チェックの「ブラウザの確認」の手順を使う。
- 実機の Safari は未確認（v0.1 から変わらず）。

## 書き出しで目で確かめること

- PDF: アラビア文字の連結、右から左の並び、日本語、転写記号（ʿ、ḥ など）とトルコ語の文字を、Chromium で画像にして確かめた。Acrobat、Illustrator、Inkscape で開くことは未確認。
- PDF の文字は輪郭として描くので、検索・選択はできない（設計書 D-43 の補足）。
- PNG のアラビア文字はブラウザの整形に任せる。Chromium の headless では正しかった。Safari と Firefox は未確認。

## 公開後の確認

main への統合後に、統括役が行う。

1. CI の verify → deploy が成功したことを確かめる。
2. https://qsarkbir.github.io/Relata/ に対して、Playwright Chromium で全 E2E を実行する。
3. サンプルの読み込み、射影、年表と再生、欠損の一覧、PDF の書き出し（フォントがこのサイトから読み込まれること）を、公開サイトで確かめる。
4. 結果をこの文書と進行表に記録し、T2-10 を ✅ にする。
