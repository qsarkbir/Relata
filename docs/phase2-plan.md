## 1. 範囲

| 区分 | Must | Should |

FR-MT-05 の注意の判定は、フェーズ 1 で core と指標パネルに実装済み。フェーズ 2 では、射影の後に注意が正しく消えることを確かめる。

### 1.2 画面についての方針（2026-11-23 の利用者の指示の要約）
- フェーズ 2 は機能の実装を優先する。全画面の再デザイン、CSS の大規模な置き換え、UI ライブラリの移行は行わない。UI 全体の洗練はフェーズ 2〜4 の後に行う。
- 既存の計算、データ形式、検索とフィルタの意味、保存と復元の互換性を保つ。
- 研究対象を表示する領域（グラフ、後の地図）を優先する。新しい設定を、図の上に常時展開して積み重ねない。
- 適用中の条件は、設定を閉じていても見えるようにする。表示するのは**実際に適用されている値**で、未適用の入力値と混同させない。
- 共通の状態（データ、フィルタ、選択、時間）と、ビューごとの表示設定を分け、その区別を画面でも示す。
- 後続フェーズの未実装の機能について、空のタブや動かないボタンを置かない（地図のタブはフェーズ 3 で足す）。

## 2. 決める論点（R-14〜R-24）

「判断」の欄が「利用者」のものは、作業を始める前に確認したい。

| ID | 論点 | 推奨 | 判断 |
|---|---|---|---|
| R-14 | 時間フィルタと年表が見る日付。今の `time` のフィルタは要素の `time`（期間）しか見ない。Palladio 式 1 表で読み込むと日付は属性（`valueType: 'date'`）になるため、サンプルでは時間で絞り込めない | 時間フィルタに日付の出どころ `source` を持たせる: `{ kind: 'span' }`（要素の期間）か `{ kind: 'attr'; attr }`（日付の属性）。複数値の日付は「どれか 1 つが条件に合えば通す」（カテゴリの複数値と同じ。D-21）。年表も同じ `source` で選ぶ | 統括役 |
| R-15 | プロジェクトファイルの版 | フェーズ 2 の型の追加（フィルタの種類、配置の方式、確からしさなど。D-24 で版を上げる対象）を、**版 2 への 1 回の更新**にまとめる。版 1 → 2 の移行関数を置き、v0.1 のファイル（公開サンプルを含む）が開けることをテストする（FR-PJ-03）。フェーズ 2 の間は版 2 を「開発中」とし、v0.2 の公開で確定する（未公開の版なので、途中で要素を足しても版を上げない）。**v0.1 のアプリでは v0.2 で保存したファイルを開けない**（「新しい版のファイル」と伝える）。 | 利用者（互換性の確認） |
| R-16 | 確からしさ（FR-DM-06）を何に持たせ、どう読むか。型の上では、属性の値と日付にはすでに `certainty` がある | (1) 関係そのものの確からしさとして、`GraphEdge` と `GraphNode` に任意の `certainty` を足す。(2) 読み込みで「確からしさ」の列を対応づけられるようにする（`確実／おそらく／可能性あり`、`certain/probable/possible`、`?`、`??` を受け付け、読めない値は警告）。(3) 属性の値の末尾の `?` を「可能性あり」と読むのは、列ごとの選択（既定は無効。原文の文字列が変わるため）。(4) フェーズ 2 では、ファセットでの絞り込み、表の列、書き出しで使う。見た目（線の種類など）への割り当ては破線（欠損）と紛れるので、UI 刷新の課題に回す | 利用者 |
| R-17 | 時間の再生（FR-TM-02）が何を変えるか | **表示だけを変える**。再生中の時刻より後の要素を薄くする（累積）か、窓の外を薄くする（移動窓）。フィルタと指標は変えない（再生のたびに指標を計算し直さない。軽い表示の変更として扱う）。時刻で絞り込みたいときは、年表の範囲選択（時間フィルタ）を使う。画面にもこの違いを書く | 統括役（気になれば利用者） |
| R-18 | 射影（FR-GR-03〜05）を処理のどこに入れるか | `applyFilters` → `buildGraph`（重みの集約）→ **射影** → 指標・配置。フィルタは射影の前の元のデータにかかる（組織を絞り込めば、射影の根拠からも外れる）。射影の設定は `GraphOptions.projection`（任意）に置く。射影したエッジは、根拠の相手ノードの一覧（`via`）と、元のエッジ ID の一覧を持つ。表ビューは元のデータ（射影前）を表示する | 統括役 |
| R-19 | 選択の状態の置き場所（FR-TB-02、FR-VG-09） | `GraphView` の中の選択を、state の `selectionStore` に移す。持つのは**ノード ID と元のエッジ ID**の集合（集約・射影したエッジは、元のエッジ ID の一覧で対応づける）。プロジェクトには保存しない（一時的な状態。§10 の uiStore と同じ扱い）。フィルタで見えなくなった要素の選択は、消さずに「表示されていない」と示す | 統括役 |
| R-20 | グラフ上の範囲選択（FR-FL-11）をフィルタにする方法 | 範囲選択はまず**選択**にする（Shift ＋ ドラッグの矩形）。選択の欄の「選択したノードで絞り込む」で、ノードの ID の集合のフィルタ（新しい種類 `nodeSet`）を足す。年表の範囲選択は、時間フィルタを足すか置き換える（既存の即時反映に合わせ、ドラッグを離した時点で適用。Undo で戻せる） | 統括役 |
| R-21 | 欠損率の一覧（FR-VG-12）の数え方 | 絞り込み後の集合で数え直し（共通規約）、全体の値を並べて示す。属性ごとに、理由別の件数と割合。時期ごとの欠損率は、年表と同じ日付の出どころと区切り（年・10 年・25 年・100 年）で数え、年代のない要素は別の行にする | 統括役 |
| R-22 | PDF（FR-OUT-04、NFR-09）のフォント | Noto Sans JP と Noto Naskh Arabic（SIL OFL）を**このサイトから配信**し、PDF を書き出すときだけ読み込む（外部のサーバーへは通信しない。NFR-02）。使った文字だけに絞って埋め込む（T2-08 で変更: 文字は整形した字形の輪郭として描き、フォントは埋め込まない。PDF の文字は検索できない。設計書 D-43 の補足）。初めての PDF 書き出しで数 MB を読み込むことを画面に示す。フォントとライセンスを「このツールについて」に載せる | 利用者（容量の確認） |
| R-23 | ビューの配置の保存（FR-PJ-01 の「ビューの配置」） | 下の段（§3）で開いているタブ、開閉、高さと、表・年表の設定を `view` の任意の項目として保存する。左右のパネルの開閉は、今のまま保存しない（既存の挙動を変えない） | 統括役 |
| R-24 | 表示する暦（FR-TM-09）の置き場所 | 全ビューに共通の表示設定として `view.display.calendar`（`gregorian`／`hijri`／`both`）に保存する。年表の目盛り、表、適用中のフィルタの説明、選択の欄の日付に効く。内部の値（JDN）は変えない | 統括役 |

### 3.1 各領域
| 領域 | 置くもの | 備考 |
|---|---|---|
| **適用中の条件**（中央の上の 1 行。新規） | 表示件数／全体（FR-FL-09 と同じ計算の結果）、適用中のフィルタの数、構築（重み・自己ループ・射影）、時間フィルタの期間、再生中の時刻、表示する暦 | 各項目は、その設定を開くボタンを兼ねる（例: 「フィルタ 3」で左のパネルを開いて一覧へ移る）。**ストアの適用済みの値だけ**から作る。項目は、その機能が実装されてから出す |
| **グラフのツールバー**（新規。既存の操作を移す） | 検索、選択中のノード（解除）、入／出の強調、ズーム、全体を表示、「表示の設定」の開閉 | 探索中に繰り返す操作を 1 行に集める |

| **ネットワークの構築**（「構築」の項目から開く小さなパネル） | 重みの集約、自己ループ（既存の設定を移す）、射影（射影先の型、仲介する型、重み付けの方式） | **グラフと指標に共通**と明記する。変えると指標と配置を計算し直すので、その旨と進行を示す |
| **選択中**（図の左上のカード。既存の詳細欄を移す） | ラベル、ID、固定／解除、入／出の隣接ノード、射影したエッジの根拠（FR-GR-04）、選択で絞り込む（FR-FL-11） | 畳める。表で選んでも同じカードに出る |

| **右のパネル**（既存） | 変えない | 射影の後は指標が射影後のグラフで計算されることを、全体指標の見出しの横に示す |

### 3.2 表示できないデータの扱い
- **地理座標の配置**（T2-03）: 座標のないノードは、図の端の「座標なし」の列にまとめて置き、件数を示す。図から消さない。
- **年表**: 年代のないノード・エッジの件数を、軸の外に別に示す（FR-TM-05）。絞り込みで除いた件数とは別の数として扱う。
- **再生中**: 時刻の外の要素は薄くするが消さない。表と件数は変えない（R-17）。
- 「表示されていない」理由（絞り込み、座標なし、年代なし、再生中の時刻の外）を、それぞれ別の文言で示す。

## 4. 状態の扱い

| 状態 | 置き場所 | 共有の範囲 | 保存 |
|---|---|---|---|
| データ（`Dataset`） | `dataStore`（既存） | 全ビュー | する |
| フィルタ（`FilterState`。時間フィルタ、`nodeSet` を含む） | `filterStore`（既存） | 全ビュー | する |
| 構築の設定（重み、自己ループ、射影） | `view.graph.graphOptions`（既存の位置のまま。`selectGraphOptions` で指標と共有） | グラフと指標 | する |
| 選択（ノード ID、元のエッジ ID） | `selectionStore`（新規） | 全ビュー | しない |
| 時間の状態（`TimeState`: 時刻、累積／移動窓、窓の幅、速度、再生中か） | viewStore（新規の `view.time`） | 全ビュー（フェーズ 3 で地図も） | する（再生中かどうかは除く） |
| 表示する暦 | `view.display.calendar`（新規） | 全ビュー | する |
| グラフの表示（配置、見た目、ラベル、向き、viewport、欠損の表示） | `view.graph`（既存。欠損の表示を足す） | グラフだけ | する |
| 表の表示（ノード／エッジ、並べ替え、表示する列、ページ） | `view.table`（新規） | 表だけ | する（ページは除く） |
| 年表の表示（日付の出どころ、区切りの幅） | `view.timeline`（新規） | 年表と欠損の時期別の一覧 | する |
| 下の段（タブ、開閉、高さ） | `view.workspace`（新規） | — | する（R-23） |
| 左右のパネルの開閉、ダイアログ、進行表示 | `uiStore`（既存） | — | しない |
| 指標、配置の結果、シーン、欠損率、年表の集計 | 計算結果のキャッシュ（ストアに入れない） | — | しない |

- ビューの切り替え、パネルや下の段の開閉では、フィルタ、選択、時間、各ビューの viewport と並べ替えを初期化しない。初期化するのは、データを置き換えたときだけ（既存の `bindGraphViewToData` と同じ考え方）。
- 新しい `view` の項目は、D-24 のとおり任意の項目として足し、無ければ既定値で補う。
- 集計（欠損率、年表、表の件数）は、絞り込み後の集合から毎回計算し直す。

### 4.1 軽い表示の変更と、計算し直す操作
| 種類 | 例 | 扱い |
|---|---|---|
| 軽い表示の変更 | ラベル、向きの表現、色・大きさ、欠損の破線、暦、再生、表の並べ替え | 即時に反映（今のまま） |
| 計算し直す操作 | フィルタ、重み、自己ループ、射影 | 即時に反映し、指標と配置を計算し直す。進行を示し、取り消せる（既存の仕組み） |
| 明示的な計算 | 配置の方式の変更、再配置 | 今のまま。ボタンで始める |

- 「適用」のボタンは、入力の途中の値を持つ欄（時間フィルタの日付の文字入力）だけに置き、Enter でも適用する。適用前の値は欄の中だけに出し、適用中の条件の行には出さない。
- 「保存」はプロジェクトのファイルの保存だけを指す（§5 の 4）。設定の反映を「保存」と呼ばない。

## 6. 共通部品とデザイントークン

- `src/app/tokens.css` を作り、色、余白、文字の大きさ、境界線、角の丸み、フォーカスの線を CSS 変数（`--rl-…`）にする。**新しく作る画面だけ**に使う。既存の CSS への適用は UI 刷新の課題にする。
- 色は 2 系統に分ける。
  - 操作の色（`--rl-accent`、`--rl-focus`、`--rl-selected`）: 選択、フォーカス、押されたボタン。
  - データの色: `core/encode` の配色（Okabe-Ito、viridis）と、強調の入／出の色（既存）。操作の色に使わない。
- 共通部品は `src/views/ui/` に、今回繰り返し使うものだけを置く: 折りたたみの節（見出しつき）、ラベルつきの欄、ツールバー、条件の項目（チップ）、状態の表示（処理中／データなし／該当なし／エラーを型で区別する 1 つの部品）、タブ（下の段で使う）。既存の `IconButton`、`InfoTip`、`ModalDialog`、`SidePanel` はそのまま使う。
- 表示の部品に分析やデータの加工を書かない。集計（欠損率、年表のビン、表の行）は `core` の純粋な関数、ストアとの橋渡しは `state` のセレクタか views のフックに置く。
- 参考の方向: 配置は Linear のように整然と（揃った行、控えめな境界線）、文字組みは Notion のように落ち着かせる（本文 14〜15px 相当、行間 1.5 前後）。クリックの領域は 32px 以上を保つ。
- 文字: 利用者の値は `<bdi>` か `dir="auto"` で隔離する。長い名前は省略記号で切り、`title` で全体を出す。アラビア文字のダイアクリティカルマークが切れないよう、行の高さを詰めすぎない。
- 操作: 入力欄にはラベルを付ける。キーボードで操作でき、フォーカスの線が見える（既存の `:focus-visible` を使う）。下の段のタブは、矢印キーで移れるタブの作法（`role="tablist"`）に従う。
