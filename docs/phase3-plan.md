### 1.2 画面についての方針（フェーズ 2 の方針 §1.2 を引き継ぐ）
- 機能の実装を優先し、全画面の再デザインはしない。ただし、地図には大きさの決まった枠が要るので、**画面の高さの整理だけを前倒しする**（R-28）。
- 研究対象を表示する領域（グラフ、地図）を優先する。地図の設定は、グラフと同じく既定で閉じた「表示の設定」の引き出しに入れる。
- 共通の状態（データ、フィルタ、選択、時間）は、グラフと地図で同じものを使う。ビューごとの表示設定（背景、束ねる設定など）は分ける。
- 未実装の機能について、空のタブや動かないボタンを置かない。

## 2. 決める論点（R-25〜R-38、R-11）

「判断」の欄が「利用者」のものは、作業を始める前に確認したい。

| ID | 論点 | 推奨 | 判断 |
|---|---|---|---|
| R-25 | 座標の出どころ。読み込みで緯度・経度の列を指定すると `GraphNode.geo` に入る（公開サンプルもこの形）。一方、T2-03 の「地理座標」の配置は属性の組（`view.graph.geoAttrs`）しか見ないので、**サンプルでは地理座標の配置が使えない** | 出どころを `{ kind: 'geo' }`（`GraphNode.geo`。既定）か `{ kind: 'attrs'; lat; lon }`（属性の組）から選ぶ形にし、地理座標の配置と地図で同じ設定・同じ関数（core）を使う。既存の `geoAttrs` は `attrs` として読む（任意の項目の読み替えなので版を上げない） | 統括役 |
| R-26 | 書簡の発信地・受信地のように、**エッジごとの地点**を扱うか。人物は移動するので、人物の座標を 1 つに決めると、書簡の実際の経路と違う図になる | フェーズ 3 はノードの座標だけで描く。移動を表したいときは、場所を別の型のノードとして読む（人物—場所の k-partite）。エッジに任意の `sourceGeo`／`targetGeo` を足す案はフェーズ 4 の候補にし、要件定義書に追記する | **利用者** |
| R-27 | 地図のビューの置き場所 | 中央の主な領域に「グラフ｜地図」の切り替え（タブ）を置く。下の段（年表・表・欠損）と左右のパネルは共通のまま。切り替えても、地図とグラフの部品は描いたまま隠し、viewport や計算結果を失わない。グラフと地図を並べる分割表示は UI 刷新の課題にする | **利用者** |
| R-28 | 画面の高さ。今はサンプルを読み込むと、左のパネルのせいでページが窓より高くなり（900 px の窓で約 1,670 px）、年表は約 90 px しか残らない | アプリを窓の高さに収め、左右のパネルは中だけでスクロールさせる。中央は図（グラフ／地図）と下の段で高さを分け合い、どちらにも下限を設ける（図 240 px、下の段 120 px）。地図を足す前のタスク（T3-00）として行う | **利用者** |
| R-29 | 依存の追加と読み込みの重さ | maplibre-gl 6.19（BSD-3-Clause）、@deck.gl/core・layers・mapbox 9.4（MIT）、d3-geo 3.1（ISC）を足す。**@deck.gl/geo-layers は入れない**（TripsLayer のために、h3 や 3D タイルなど使わない依存を多く引き込むため）。粒子は ScatterplotLayer の位置を時刻から補間して描く（設計 §9.3 の「TripsLayer を使う」を変える）。地図の部分は動的 import にし、**地図を初めて開いたときだけ**読み込む（普段の起動を重くしない）。増える容量は実測して完了報告に書く（目安は gzip で 500〜700 KB） | **利用者**（容量） |
| R-30 | 背景地図と外部通信（NFR-02） | (1) 地図のタブを開くまで、タイルを取りに行かない。(2) 既定は OpenStreetMap のラスタータイル。帰属表示「© OpenStreetMap contributors」（著作権のページへのリンク）を右下に常に出す。(3) 簡易背景として Natural Earth の陸地（1:50m、パブリックドメイン）を同梱し、地図を開いたときだけこのサイトから読む。(4) 利用者の XYZ の URL は `https:` だけを受け付け、`{z}`、`{x}`、`{y}` を必須にし、帰属表示の文（古地図の出典など）を利用者が書く欄を置く（空なら URL のホスト名を出す）。(5) MapLibre の文字の層（glyphs）は使わない（外部のフォント配信が要るため）。(6) タイルを取るとき、表示中の範囲がタイルのサーバーに伝わることを、地図の設定と「このツールについて」に書く。(7) E2E は簡易背景か、タイルを `page.route` で差し替え、OSM に通信しない。(8) **OSM のタイルの利用規約は、この環境から規約のページに届かず、まだ確かめていない**。T3-03 の前に確かめ、既定にしてよい使い方か（大量利用の扱い、書き出した画像の帰属）を確認する | **利用者** |
| R-11 | `src/map/` の ESLint の規則と、タイルの API キー（既存の論点） | `src/map/` は state、views、app、io、workers を import しない（§4.1）。DOM と WebGL は使ってよい（画面の層のため）。`Date` と `Math.random` は使わない。タイルの URL は `view.map` に保存するが、クエリの中の鍵らしい項目（`key`、`apikey`、`api_key`、`access_token`、`token` など）は保存の前に除き、開いたときに「鍵を入れ直してください」と示す。鍵は自動保存にも `localStorage` にも残さない | 統括役 |
| R-31 | 地図のラベル（NFR-09） | deck.gl の TextLayer は使わない（アラビア文字の連結と左右の向きの処理をしないため）。ラベルは地図の上に重ねた SVG の層で、ブラウザに文字を描かせる。重なりの解消は `render/labels` の算法を、地図の画面座標で使う | 統括役 |
| R-32 | 地図の図形と書き出しの一致（設計 §8.1 の原則を地図にも） | 「地図のシーン」（ノード、エッジの経路、矢じり、ラベル、凡例）を Web メルカトルの平面座標で作り、画面（deck.gl）と SVG の書き出し（d3-geo の同じ投影）が同じものを描く。地図は平面とし、傾きと回転を使わない（ArcLayer の立体の弧は使わない）。弧は平面の 2 次曲線で、往復の分離・縁での切断・矢じりは `render/edges` の幾何をそのまま使う。ノードとエッジの大きさは画面の px で保ち（設計 3.8 のグラフと同じ）、縁での切断と矢じりはズームが止まってから作り直す | 統括役 |
| R-33 | edge bundling の範囲と計算し直す時機（FR-VG-13、14） | グラフ図と地図の両方で使える（設定はビューごとに別）。Worker で、グラフはレイアウトの座標、地図はメルカトルの平面座標（ズームで変わらない）に対して計算する。計算し直すのは、フィルタ、構築、配置、束ねる設定が変わったときだけで、ズーム、パン、再生では計算しない。逆向きのエッジは別の車線に分ける（Divided Edge Bundling）。描き方は「束の太さの帯」（FR-VG-14。既定）と「半透明の重ね描き」（簡易版）。束ねた経路の向きの表現は先細りを勧め、矢印を選んだときは経路の終端に付ける。5,000 本を超えたら警告し、計算を始めるかを選ばせる | 統括役 |
| R-34 | 地図の時間アニメーション（FR-MP-03） | 時刻と再生は既存の `view.time` と `usePlaybackClock` を共有する（地図の時計を作らない）。(1) エッジは、日付の最も早い日に現れ始め、最も遅い日に完全に現れる（設計 §9.2。幅のある年代を見た目で示す）。移動窓では窓から外れると薄れる。(2) 粒子は、エッジの日付の幅の間、送り手から受け手へ動く。日付のないエッジと無向のエッジには粒子を出さない。(3) ノードは、その時点までの累積の次数（表示中のエッジのうち、時刻までに現れたもの）で大きくなる。大きさの目盛りは全期間を通した最大にそろえる（時点で目盛りが変わると比べられないため）。累積の次数は年表の区切りごとに前もって数え、再生中は引くだけにする。(4) 束ねた経路では、区間と通るエッジの対応を前もって作り、現れているエッジの重みだけで太さを出し直す（軽い表示の変更） | 統括役 |
| R-35 | 時点ごとの指標（利用者の着想。2026-11-24。要件定義書にはまだ無い） | フェーズ 3 では R-34 の累積の次数だけを入れる。媒介中心性などの時点ごとの値（区切りごとの部分グラフで Worker が前もって計算、選んだノードの値の折れ線、時点ごとの CSV）は、要件 FR-MT-07（Should）として要件定義書に足し、**フェーズ 3 の最後の任意のタスク（T3-09）**にする。決めることは、幅のある年代の扱い、日付のないエッジ、その時点にいないノード（欠損）、小さなグラフでの値の不安定さの注意 | **利用者** |
| R-36 | 地図上の範囲選択のフィルタ（FR-MP-04、filter-audit #11） | Shift ＋ ドラッグの矩形で選択する（グラフと同じ操作。D-41）。選択の欄に「この範囲で絞り込む」を出し、新しい種類のフィルタ `geo`（`{ kind: 'geo'; bbox: { west; south; east; north }; missing }`。ノード専用）を足す。ID の一覧（`nodeSet`）でなく範囲で持つのは、適用中の一覧で「緯度 30〜36°、経度 −10〜0°」と読めるため、座標の出どころ（R-25）を変えても意味が保たれるため。座標のないノードは欠損として `missing` の指定に従う（既定は除く。除いた件数を示す）。経度 180° をまたぐ範囲（west > east）も扱う。射影の適用中は `nodeSet` と同じく仲介の型を通す | 統括役 |
| R-37 | プロジェクトファイルの版 3 | `geo` のフィルタはフィルタの種類の追加なので、D-24 により `formatVersion` を 3 に上げる（版 2 → 3 の移行は中身を変えない）。地図の設定 `view.map`（表示中のビュー、背景、タイルの URL〔鍵を除く〕と帰属表示の文、viewport、エッジの描き方、束ねる設定、ラベル）と `view.graph.bundling` は任意の項目として足す。フェーズ 3 の間は版 3 を開発中とし、v0.3 の公開で確定する。**v0.2 のアプリは v0.3 で保存したファイルを開けない**（「新しい版」と伝える） | **利用者**（互換性） |
| R-38 | 地図の書き出し（FR-OUT-06）と座標のないノード（FR-MP-05） | 「書き出し」のダイアログに「地図」を足す。PNG は地図の Canvas を倍率（1・2・4 倍）を上げて描き直し、タイルを含める。**画像にも帰属表示を描く**。SVG は d3-geo で、簡易背景、ノード、エッジ、ラベル、凡例、出典表記を描き、タイルは含まない（ダイアログにその旨を出す）。地図の PDF はフェーズ 4 の候補。座標のないノードは、地図の横に「地図に載らないノード N 件」の開閉できる一覧を出し、理由（座標の列が無い、欠損、範囲外）ごとに数える。片端が座標なしのエッジも件数を示す | 統括役 |

### 3.1 各領域
| 領域 | 置くもの | 備考 |
|---|---|---|
| **ビューの切り替え**（中央のツールバーの先頭。新規） | 「グラフ｜地図」のタブ（`role="tablist"`） | 座標を持つノードが 1 つも無いときも地図は開けるが、空の地図と「座標の出どころを選んでください」の案内を出す |
| **地図のツールバー** | 検索、選択、ズーム、全体を表示、束ねるの切り替え、「表示の設定」 | グラフのツールバーと同じ並びにする（検索と選択は共通の部品） |
| **地図の表示の設定**（右端の引き出し） | 背景地図（OSM／簡易背景／自分の XYZ の URL と帰属表示の文、通信についての注意）、座標の出どころ（R-25）、ノードとエッジ（大きさ・色は既存の `EncodingControls`、直線／弧、向きの表し方）、束ねる（強さ、反復回数、描き方）、ラベル、再生中の表示（粒子、累積の次数） | **地図だけの設定**と見出しに書く。座標の出どころはグラフの地理座標の配置と共通なので、その旨を書く |
| **グラフの表示の設定** | 「束ねる」の節を足す | 他は変えない |
| **地図に載らないノード**（地図の左下。新規） | 件数のボタンと、開くと理由別の一覧 | 一覧のノードを選ぶと、選択中のカードに出る（表と同じ連動） |
| **帰属表示**（地図の右下） | 背景の帰属表示 | 常に出す。消す設定を置かない |
| **選択中のカード** | 既存のものをそのまま地図でも使う。範囲選択の後は「この範囲で絞り込む」 | — |

### 3.2 表示できないデータの扱い
- 座標のないノードは地図に描かず、件数と一覧で示す（FR-MP-05）。片端が座標なしのエッジも件数を示す。
- 「表示されていない」理由（絞り込み、座標なし、年代なし、再生中の時刻の外）を、グラフと同じく別の文言で示す。
- bundling を計算中・中止・失敗したときは、束ねない図を描いたまま状態を示す（図を消さない）。

## 4. 状態の扱い

| 状態 | 置き場所 | 共有の範囲 | 保存 |
|---|---|---|---|
| データ、フィルタ（`geo` を含む）、構築の設定 | 既存のまま | 全ビュー | する |
| 選択 | `selectionStore`（既存） | グラフ、地図、表 | しない |
| 時間の状態 | `view.time`（既存） | グラフ、地図、年表 | する（再生中かは除く） |
| 座標の出どころ（R-25） | `view.geoSource`（新規。既存の `view.graph.geoAttrs` から読み替え） | グラフの地理座標の配置と地図 | する |
| 表示中のビュー（グラフ／地図） | `view.workspace.mainView`（新規） | — | する |
| 地図の表示（背景、タイルの URL と帰属表示の文、viewport、エッジの描き方、ラベル、再生中の表示） | `view.map`（新規） | 地図だけ | する（タイルの鍵は除く。R-11） |
| 束ねる設定（有効か、強さ、反復回数、描き方） | `view.graph.bundling`、`view.map.bundling`（新規） | それぞれのビュー | する |
| 束ねた経路、地図のシーン、累積の次数の表 | 計算結果のキャッシュ（ストアに入れない） | — | しない |
| MapLibre と deck.gl のインスタンス | `src/map/` の部品の中 | — | しない |

- `src/map/` はストアを読まない。views の薄い部品（`MapView.tsx`）がストアを読み、値と更新の関数を props で渡す（§4.1、§9.2）。
- bundling は既存の Worker の仕組み（`*.client.ts`、state の controller で版番号と中止）に合わせ、`src/state/bundlingController.ts` を置く（D-17 の補足と同じ形）。
- ビューの切り替え、パネルや下の段の開閉では、フィルタ、選択、時間、各ビューの viewport を初期化しない（フェーズ 2 と同じ）。

### 4.1 軽い表示の変更と、計算し直す操作
| 種類 | 例 | 扱い |
|---|---|---|
| 軽い表示の変更 | 背景の切り替え、ズーム、パン、再生、粒子、ラベル、束の描き方の切り替え（帯／重ね描き） | 即時に反映。bundling は計算し直さない |
| 計算し直す操作 | フィルタ、構築、配置、座標の出どころ | 即時に反映し、束ねる設定が有効なら bundling も計算し直す（進行を示し、取り消せる） |
| 明示的な計算 | 束ねる強さ・反復回数の変更 | 「束ね直す」のボタンで始める（重いため。5,000 本を超えるときは確認） |

## 5. タスクの分け方と順序

## 7. 外部通信とプライバシー（NFR-02）

- 外部への通信は、地図のタブを開いた後のタイルの取得だけ。利用者のデータ（ノード、属性、ファイル）はタイルの要求に含めない。
- タイルの要求から、表示している範囲とズームがタイルのサーバーに伝わる。地図の設定と「このツールについて」に書き、簡易背景（通信なし）を選べることを示す。
- 利用者の XYZ の URL は `https:` だけ。鍵はプロジェクトファイル、自動保存、`localStorage` に残さない（R-11）。
- E2E で「地図を開くまで外部へ通信しない」「簡易背景では外部へ通信しない」を確かめる（既存の外部通信の検査と同じ形）。
