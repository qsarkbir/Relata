## 1. 背景と目的

### 1.1 背景
Palladio（Stanford Humanities + Design、BSD-3-Clause）は、人文学の研究者が表データから地図・グラフ・年表を手軽に作れるブラウザアプリとして広く使われてきた。一方で、次の課題がある。

- 2019 年以降は開発が止まっており、古い技術（AngularJS 1.x、d3 v3）に依存している。
- データモデルが「1 行 ＝ 1 エッジ」で、ノードは名前の文字列としてしか扱えない。そのため、ノード単位の絞り込み、同名異人の区別、k-partite グラフの扱いができない。
- 有向グラフと無向グラフの区別がなく、指標も無向として計算される。
- フィルタに不具合がある（[filter-audit.md](filter-audit.md)）。

### 1.2 目的
Palladio の基本機能（表データの読み込み、ファセットと時間による絞り込み、グラフ・地図・表の連動表示、プロジェクトの保存）を引き継ぎ、歴史ネットワーク研究に必要な機能を備えたツール **Relata** を作る。

### 1.3 名称
**Relata**（ラテン語で「関係づけられたもの」）。Palladio に由来することは README と画面の「このツールについて」に明記する。

## 2. 利用者と利用場面

### 2.1 想定する利用者
| 利用者 | 特徴 |
|---|---|
| 歴史研究者 | 史料から作った表データを持つ。ネットワーク分析は初心者から中級者。**西アジア史の研究者を主な利用者として想定する**。ヒジュラ暦の日付や、アラビア文字（アラビア語、ペルシア語、オスマン語）の人名・地名を扱う |
| デジタル・ヒューマニティーズの研究者 | 指標や書き出しを論文に使う。他のツール（Gephi、networkx、R）と行き来する |
| 教員と学生 | 授業で、サンプルデータを使って操作する |
| 旧 Palladio の利用者 | これまでと同じ操作感で使いたい |

### 2.2 利用場面（ユースケース）
| ID | 場面 |
|---|---|
| UC-1 | 書簡の表（差出人、受取人、日付）を読み込み、有向グラフとして送受信の偏りを見る。中心性でノードの大きさを変え、論文用に SVG で書き出す |
| UC-2 | 人物と組織の所属関係（二部グラフ）を読み込み、人物どうしのネットワークに射影する。射影されたつながりの根拠（共通の組織）をたどる |
| UC-3 | 書簡の流れを、地図上で時間とともにアニメーション表示する。多数の流れを束ねて（edge bundling）主な経路を見る |
| UC-4 | 欠損の多いデータで、どの属性・どの時期に欠損が偏っているかを確かめ、欠損を含めた場合と除いた場合でネットワークの見え方を比べる |
| UC-5 | ヒジュラ暦で日付が記された史料や、年代に幅のある史料（「1050 年頃」など）を読み込み、西暦に換算して、幅を保ったまま時間で絞り込む |
| UC-6 | 作業の状態をファイルに保存し、後日または共同研究者の環境で同じ図を再現する |

## 3. 用語

| 用語 | 意味 |
|---|---|
| ノード | 人物、組織、場所、書簡など、ネットワークの点 |
| エッジ | ノード間の関係。有向（向きがある）または無向 |
| 混在グラフ | 有向エッジと無向エッジが共存するグラフ |
| ノード型、部 | ノードの種類。k-partite グラフでは各型が 1 つの「部」になる |
| 射影（projection） | 二部グラフを片方の型だけのグラフに変換すること。共通の相手を持つノードどうしをつなぐ |
| 欠損 | 値がないこと。Relata では理由（記載なし、史料の亡失、判読不能、該当なし）を持たせる |
| 幅のある年代 | 「1650 年頃」「1640〜1660 年のどこか」のように、日付が 1 点に定まらない値 |
| フィルタ | ノードやエッジを条件で絞り込む仕組み |
| ファセット | 属性の値ごとの件数を一覧にし、値を選んで絞り込む UI |
| 指標 | 次数、中心性など、ネットワークの構造を数値で表したもの |
| エンコーディング | 指標や属性を、大きさ・色・太さなどの見た目に割り当てること |
| Edge bundling | 似た経路のエッジを束ねて描き、図を読みやすくする手法 |
| プロジェクト | データと表示状態（フィルタ、配置、見た目の設定）をまとめたもの |

## 4. 機能要件

**優先度**: Must（なければリリースしない）／Should（できる限り入れる）／Could（余裕があれば入れる）
**フェーズ**: 開発する時期（[設計書 §19](design.md)）

### 4.1 データの読み込み（FR-IN）

| ID | 要件 | 優先度 | フェーズ |
|---|---|---|---|
| FR-IN-01 | CSV と TSV を読み込める。文字コードは UTF-8 と Shift_JIS に対応し、自動で判定する（手動でも指定できる） | Must | 1 |
| FR-IN-02 | Excel（.xlsx）を読み込める。シートを選べる | Must | 1 |
| FR-IN-03 | 「ノード表＋エッジ表」の 2 表で読み込める（§6.1、§6.2） | Must | 1 |
| FR-IN-04 | Palladio 式の 1 表で読み込める。利用者が「始点の列」と「終点の列」を選ぶと、各列がノード型になり、各行がエッジになる。残りの列は、エッジの属性にするか、どちらかのノードの属性にするかを選べる（§6.3） | Must | 1 |
| FR-IN-05 | 各列の型（文字列、数値、日付、真偽、カテゴリ）を推定して示し、利用者が変更できる。複数値の列には区切り文字を指定できる。日付の列には暦（§6.4）を列ごとに指定できる | Must | 1 |
| FR-IN-06 | 読み込み時の問題を、行番号つきの警告として一覧表示する。対象は、ID の重複、存在しないノードを指すエッジ、解析できない日付、範囲外の座標、型の合わない値。問題のある行も黙って捨てない | Must | 1 |
| FR-IN-07 | 空欄を欠損（記載なし）として読み込む。利用者が「欠損を表す記号」と理由を対応づけられる（例: 「〔欠〕」→ 史料の亡失、「□」→ 判読不能）（§6.5） | Must | 1 |
| FR-IN-08 | Relata のプロジェクトファイル（JSON）を読み込める | Must | 1 |
| FR-IN-09 | サンプルデータを 1 クリックで読み込める | Should | 1 |
| FR-IN-10 | GEXF と GraphML を読み込める | Could | 4 |
| FR-IN-11 | 旧 Palladio のプロジェクトファイル（JSON）を読み込める | Could | 4 |

### 4.2 データモデル（FR-DM）

| ID | 要件 | 優先度 | フェーズ |
|---|---|---|---|
| FR-DM-01 | ノードを、名前ではなく ID で識別する。ID のない表では「型＋ラベル」から ID を作る。同じ名前でも型が違えば別のノードになる | Must | 1 |
| FR-DM-02 | ノード型を定義でき、型ごとに名前・色・形を設定できる | Must | 1 |
| FR-DM-03 | グラフの種類（有向／無向／混在）を明示的に選ぶ。混在の場合は、エッジごとに有向か無向かを列で指定できる | Must | 1 |
| FR-DM-04 | 欠損を理由つきで保持する。理由は「記載なし」「史料の亡失」「判読不能」「該当なし」の 4 種 | Must | 1 |
| FR-DM-05 | 幅のある年代を、幅を保ったまま保持する（書式は §6.4） | Must | 1 |
| FR-DM-06 | 値の確からしさ（確実／おそらく／可能性あり）を保持できる | Should | 2 |
| FR-DM-07 | 複数値の属性（例: 「ラテン語; フランス語」）を、値の並びとして保持する | Must | 1 |
| FR-DM-08 | 自己ループと多重エッジ（同じ 2 点間の複数のエッジ）を捨てずに保持する | Must | 1 |

### 4.3 フィルタ（FR-FL）

| ID | 要件 | 優先度 | フェーズ |
|---|---|---|---|
| FR-FL-01 | ノード用のフィルタとエッジ用のフィルタを、別々に設定できる | Must | 1 |
| FR-FL-02 | フィルタの種類: カテゴリ（ファセット）、数値の範囲、テキスト検索、ノード型 | Must | 1 |
| FR-FL-03 | 時間範囲のフィルタ。幅のある年代については「範囲と重なる」（既定）と「範囲に収まる」を選べる | Must | 2 |
| FR-FL-04 | エッジは、エッジ自身がフィルタを通過し、かつ両端のノードが通過したときに表示する（既定）。「片方の端が通過すればよい」にも切り替えられる | Must | 1 |
| FR-FL-05 | 孤立ノード（表示されるエッジがないノード）を表示するかどうかを選べる。既定は表示しない | Must | 1 |
| FR-FL-06 | 欠損の扱い: カテゴリのファセットでは、欠損を理由ごとの項目（例: 「（欠損: 記載なし）」）として並べ、他の値と同じように選べる。数値と時間の範囲では、欠損を「除外」（既定）するか「含める」かを選べ、除外した件数を常に表示する | Must | 1 |
| FR-FL-07 | ファセットの各値に「他のフィルタを適用した後の件数 / 全体の件数」を表示する | Must | 1 |
| FR-FL-08 | 適用中のフィルタを一覧表示し、個別にも一括でも解除できる。一覧は実際の絞り込みの状態と常に一致する | Must | 1 |
| FR-FL-09 | 絞り込み後のノード数とエッジ数を、全体の数と並べて常に表示する | Must | 1 |
| FR-FL-10 | フィルタ操作を元に戻せる（Undo／Redo） | Should | 1 |
| FR-FL-11 | グラフ・地図・年表の上で範囲を選択して、フィルタにできる | Should | 2 |
| FR-FL-12 | テキスト検索とノード検索では、表記の揺れを無視して照合できる。対象は、アラビア文字の揺れ（ハムザ付きのアリフと素のアリフ、ター・マルブータとハー、アラビア文字とペルシア文字のヤーとカーフ、母音記号、タトウィール）、転写の補助記号（ā、ḥ、ṣ、ʿ、ʾ など）、大文字と小文字、アラビア・インド数字（٠–٩、۰–۹）と算用数字。照合を厳密にする設定も選べる | Must | 1 |

### 4.4 グラフの構築（FR-GR）

| ID | 要件 | 優先度 | フェーズ |
|---|---|---|---|
| FR-GR-01 | 同じ 2 点間の複数のエッジを 1 本にまとめ、重みを「件数」または「指定した数値属性の合計」で求める。有向エッジは向きごとにまとめる | Must | 1 |
| FR-GR-02 | 自己ループを表示するかどうかを選べる | Should | 1 |
| FR-GR-03 | 二部グラフを、指定した型だけのグラフに射影できる。重み付けは「共通の相手の数」「Newman 方式」「Jaccard 係数」から選べる | Must | 2 |
| FR-GR-04 | 射影でできた各エッジについて、根拠となった相手ノードの一覧を見られる | Must | 2 |
| FR-GR-05 | 3 部以上の k-partite グラフでは、「どの型を、どの型を介して射影するか」を指定できる | Should | 2 |
| FR-GR-06 | 特定のノードを中心に、指定した段数までのエゴネットワークを抜き出せる | Could | 4 |

### 4.5 ネットワーク指標（FR-MT）

| ID | 要件 | 優先度 | フェーズ |
|---|---|---|---|
| FR-MT-01 | ノードごとの指標: 次数（有向では入次数・出次数・合計）、重み付き次数、媒介中心性、近接中心性、PageRank、固有ベクトル中心性（有向では HITS）、k-core、クラスタ係数 | Must | 1 |
| FR-MT-02 | 全体の指標: ノード数、エッジ数、密度、平均次数、連結成分の数、推移性、相互性（有向のみ） | Must | 1 |
| FR-MT-03 | フィルタを変えると、指標を自動で計算し直す。計算中は進行を表示し、画面は操作できるままにする | Must | 1 |
| FR-MT-04 | 指標を表で見られ、並べ替えと CSV 出力ができる | Must | 1 |
| FR-MT-05 | k-partite グラフに、1 種類のノードを前提とする指標を当てはめるときは、注意を表示する | Should | 2 |
| FR-MT-06 | Louvain 法でコミュニティを検出し、色に割り当てられる | Should | 4 |

### 4.6 グラフの表示（FR-VG）

| ID | 要件 | 優先度 | フェーズ |
|---|---|---|---|
| FR-VG-01 | レイアウト: 力学モデル（ForceAtlas2）、円形、手動での固定（ピン留め） | Must | 1 |
| FR-VG-02 | レイアウト: 層状（k-partite 用。型ごとに列を分ける）、地理座標 | Should | 2 |
| FR-VG-03 | ノードの大きさに指標か数値属性を、色に型・カテゴリ属性・指標を、形に型を割り当てられる | Must | 1 |
| FR-VG-04 | 大きさと太さの割り当てでは、スケールを「線形」「平方根」「対数」から選べる。**既定は平方根**。最小値と最大値（ピクセル）を指定できる | Must | 1 |
| FR-VG-05 | 有向エッジの表し方を「矢印」「先細り（根元が太く先端が細い線）」「色の濃淡」から選べる。**既定は矢印** | Must | 1 |
| FR-VG-06 | 往復エッジ（A→B と B→A）を、重ねずに 2 本の弧に分けて描く | Must | 1 |
| FR-VG-07 | 矢じりはノードの中心ではなく縁で止め、大きさを線の太さに合わせる | Must | 1 |
| FR-VG-08 | エッジの太さに重みを割り当てられる（スケールは FR-VG-04） | Must | 1 |
| FR-VG-09 | ノードを選ぶと、入ってくるエッジと出ていくエッジを別の色で強調する | Must | 1 |
| FR-VG-10 | ラベルの表示方法を「すべて」「選択中のみ」「大きいノードのみ」から選べる。ラベルどうしの重なりを減らす | Must | 1 |
| FR-VG-11 | ズーム、パン、ノードのドラッグ、名前によるノード検索（照合は FR-FL-12）ができる | Must | 1 |
| FR-VG-12 | 欠損の可視化: 指定した属性が欠損しているノードとエッジを、見た目（破線など）で区別できる。属性ごと・時期ごとの欠損率を一覧で示す | Must | 2 |
| FR-VG-13 | Edge bundling を有効にできる。束ねる強さを調整できる。逆向きのエッジは別の束にする | Must | 3 |
| FR-VG-14 | Edge bundling の束の太さは、その区間を通るエッジの重みの合計にスケール（FR-VG-04。**既定は平方根**）を当てはめて決める | Must | 3 |

## 6. データ仕様

### 6.1 ノード表

| 列 | 必須 | 内容 |
|---|---|---|
| id | 任意 | ノードの ID。ない場合は「型＋ラベル」から作る |
| label | 必須 | 表示名 |
| type | 任意 | ノード型。ない場合は 1 種類として扱う |
| lat, lon | 任意 | 緯度と経度（十進数の度） |
| start, end | 任意 | 存在した期間（生没年など）。書式は §6.4 |
| その他の列 | 任意 | 属性として読み込む |

### 6.2 エッジ表

| 列 | 必須 | 内容 |
|---|---|---|
| source, target | 必須 | 始点と終点のノード ID |
| directed | 任意 | 混在グラフで、エッジごとに有向かどうか（true/false） |
| relation | 任意 | 関係の種類（書簡、婚姻、取引など） |
| weight | 任意 | 重み。ない場合は 1 |
| date、または start と end | 任意 | 関係の時期。書式は §6.4 |
| その他の列 | 任意 | 属性として読み込む |

列名は利用者が対応づけられる。上の名前でなくてもよい。

### 6.3 Palladio 式の 1 表
1 行が 1 つの関係を表す表（例: 書簡の表で、差出人と受取人の列がある）。読み込みの手順は次のとおり。

1. 利用者が始点の列と終点の列を選ぶ。
2. 各列がノード型になる（例: 差出人の列 →「人物」型）。両方の列を同じ型にもできる（例: 人物から人物への書簡）。
3. 残りの列を、エッジの属性にするか、始点または終点のノードの属性にするかを選ぶ。
4. 同じノードに、行によって異なる属性値が付いた場合は警告を出す（FR-IN-06）。

### 6.4 日付の書式

| 入力の例 | 意味 | 保持のしかた |
|---|---|---|
| `1650` | 1650 年のどこか | 1650-01-01 〜 1650-12-31 の幅 |
| `1650-03` | 1650 年 3 月のどこか | 月初 〜 月末の幅 |
| `1650-03-15` | 1650 年 3 月 15 日 | 1 日 |
| `c.1650`、`ca. 1650`、`1650頃`、`~1650` | 1650 年頃 | 前後 5 年の幅（幅は設定で変えられる） |
| `1650?` | 1650 年か、不確か | 1650 年の幅、確からしさ「可能性あり」 |
| `1640/1660`、`1640-1660`、`1640〜1660` | 1640 年から 1660 年のどこか | 1640-01-01 〜 1660-12-31 の幅 |
| `BC44`、`前44`、`紀元前44年` | 紀元前 44 年 | 内部では天文学的な年の数え方（紀元前 1 年 ＝ 0 年）で保持する |

**ヒジュラ暦**（FR-TM-06）

| 入力の例 | 意味 | 保持のしかた |
|---|---|---|
| `1050 AH`、`1050H`、`1050 هـ`、`١٠٥٠ هـ` | ヒジュラ暦 1050 年のどこか | 西暦 1640-04-23 〜 1641-04-11 の幅 |
| `Ramaḍān 1050`、`Ramadan 1050`、`رمضان ١٠٥٠` | ヒジュラ暦 1050 年ラマダーン月のどこか | 月初 〜 月末の幅 |
| `15 Ramaḍān 1050`、`1050-09-15 AH` | ヒジュラ暦 1050 年ラマダーン月 15 日 | 西暦 1640-12-29 を中心に前後 2 日の幅 |
| `c. 1050 AH`、`1050 AH 頃` | ヒジュラ暦 1050 年頃 | 前後 5 年の幅（西暦と同じ設定） |
| `1050 AH / 1640 CE`（併記） | 両暦の併記 | ヒジュラ暦の値を採用し、西暦の値と食い違えば警告する |

- **暦の指定**: 日付の列ごとに暦（西暦／ヒジュラ暦）を指定できる（FR-IN-05）。ヒジュラ暦の列では、`AH` などの印がなくても数値をヒジュラ暦として読む。西暦の列でも、`AH`、`H`、`هـ` の印があればヒジュラ暦として読む。
- **換算の方法**: 計算上の暦（30 年周期の太陰暦。Reingold & Dershowitz, *Calendrical Calculations* の方式）で換算する。実際の暦は月の観測で決まり、1〜2 日ずれることがあるため、**日付まで指定された値には既定で前後 2 日の幅を持たせる**（設定で変えられる）。
- **月の名前**: アラビア文字の表記と、一般的な転写（補助記号の有無、IJMES 式など）の両方を受け付ける。照合は FR-FL-12 と同じ正規化で行う。
- **数字**: 算用数字、アラビア・インド数字（٠–٩）、ペルシア数字（۰–۹）のいずれも受け付ける。

**共通**
- 期間（start と end）は、それぞれが上の書式を取れる。たとえば「1650 年頃から 1660 年頃まで」は、始点と終点がそれぞれ幅を持つ。
- 西暦は、指定がなければグレゴリオ暦（1582 年より前にもさかのぼって適用）とみなす。ユリウス暦、太陽ヒジュラ暦、ルーミー暦はフェーズ 4（FR-TM-07、08）。それまでは、解析できない日付として警告する。

### 6.5 欠損の表記
- 空欄は「記載なし」とする。
- 利用者は、記号と欠損理由の対応表を作れる（例: 「〔欠〕」→ 史料の亡失、「□」→ 判読不能、「—」→ 該当なし）。
- 対応表はプロジェクトに保存する。

### 6.6 プロジェクトファイル
JSON 形式。おおまかな構造は次のとおり（詳細は設計書 §11）。

```
{
  "app": "Relata",
  "formatVersion": 1,
  "savedAt": "...",
  "dataset": { ノード型、ノード、エッジ、属性の定義、欠損の対応表 },
  "view":    { フィルタ、見た目の設定、ノードの位置、ビューの配置、時間の設定 }
}
```

## 7. 制約と前提
- 想定する規模は NFR-03 の範囲とする。それを超えるデータは動作するかもしれないが、保証しない。
- ブラウザのメモリに収まるデータを扱う。
- OpenStreetMap のタイルは、その利用規約（帰属表示、大量アクセスの禁止）に従う。
- 指標の定義は networkx に合わせ、networkx と同じ値になることを確かめる。

## 8. 対象外
- サーバーへの保存、アカウント、共同での同時編集
- 10 万ノードを超える大規模なネットワーク
- 文章から人名や関係を自動で抽出する機能
- 統計モデル（ERGM など）による推定

## 9. 受け入れ基準

各フェーズは、次をすべて満たしたときに完了とする。

1. そのフェーズの **Must** の要件が、すべて実装されている。
