## 守ること
- 計算はしない。フィルタの適用、集計、指標は `src/core/` や Worker の関数を呼ぶ。コンポーネントの中で同じ処理を書き直さない。
- 「適用中のフィルタ」の表示は、ストアの FilterState から導き出す。別の状態として持たない（旧 Palladio の不具合の原因だったため。`docs/filter-audit.md` の #2, #3）。
- ストアの状態は、プロジェクトファイルに保存できる「データ」と、保存しない「一時的な UI 状態」（ホバー中のノードなど）を分ける。
- 画面に出す文字列は直書きせず、`src/i18n/` の辞書から取る。
- `src/i18n/` は `render` からも使われるので、React、Zustand、DOM、`navigator`、`Date` に依存させない（ESLint で禁止。設計書 §4.1）。ブラウザの言語などは呼ぶ側（`src/app/`、`src/state/`）が渡す。
- DOM やブラウザの機能（`document`、`requestAnimationFrame`、`navigator`、Canvas での文字の幅の測定）を直接使うのは `src/app/` と `src/views/` だけにする。`src/state/` は DOM に依存しない純粋なストアにする（設計書 §4.1）。
- 時間の再生の時計はアプリに 1 つだけ置く。state は `TimeState` と更新の関数（`tick` など）だけを持ち、`requestAnimationFrame` とタブの表示状態で `tick` を呼ぶ駆動は `src/app/` の 1 つのフックに置く。地図（`src/map/`）にはストアの値と更新の関数を props で渡す（設計書 §9.2、D-17）。
- render が返す SVG の文字列は、render がエスケープ済み（設計書 §8.1）。画面に入れる方法とイベントの付け方は、設計書 §8.1 に従う。
- Worker は `src/workers/*.client.ts` の `run` と `cancel` を通して呼ぶ。版番号は state が採番して手元で照合し、新しい依頼が来たら `cancel()` で前の計算を止める（設計書 §7.3、D-17）。views から client を直接呼ばない。
- 設計書 §16.4 の「してはいけないこと」を守る（コミット、push、ブランチの切り替え、担当範囲の外の変更をしない）。他のエージェントと同じフォルダで作業するときは、§16.4 の範囲を絞った確認を使い、`npm test` と `npm run lint` を実行しない。
- 2 回続けて同じところでつまずいたら、それ以上進めずに統括役に報告する（§16.1）。
- キーボードだけで主な操作ができるようにする。色だけで情報を伝えない。
- 重い処理の最中は進行表示を出し、画面を固まらせない。
