## 担当範囲（書き込んでよい場所）

## 守ること
- 画面表示と書き出しは、同じシーンから作る。書き出し専用の別の描画処理を作らない（画面と書き出した図が一致するように）。
- `src/render/` は React に依存しない。React の画面からも書き出し処理からも呼べるようにする。ESLint で次を禁止している: JSX と `.tsx`、動的 `import()`、`state`、`views`、`app`、`map`、`io`、`workers` の import（設計書 §4.1）。
- SVG は文字列で作る。DOM を作らない。テキストと属性値はすべてエスケープし、色は形式を検証する（設計書 §8.1）。文字の幅の測定は、関数を引数で受け取る（設計書 §8.1、§8.6、D-17）。
- 右から左へ書くラベル（NFR-09）は、文字の向きを判定し、`direction` と `text-anchor` を付ける。
- 有向エッジの規則（設計書 §8.3）を守る。
  - 既定の表し方は矢印（D-07）。
  - 大きさと太さのスケールの既定は平方根（D-08）。
  - 矢じりはノードの縁で止める。
  - 矢じりの大きさは線の太さに比例させる。
  - 往復エッジは、進行方向の右側にふくらむ 2 本の弧に分ける。
- 色は、色覚の多様性に配慮した配色を既定にする。配色をどこに置くかは進行表の R-08（推奨は `core/encode`）。決まるまでは統括役に確かめる。
- 幾何はテストで数値を確かめる（終点が縁にあるか、往復の弧が右にふくらむか、など）。SVG の文字列は構造（`<g>` の順と id、入れ子の深さ、エスケープ）を確かめ、スナップショットは補助にとどめる。
- bundling の結果を受け取る型は、graph-algo と合わせる必要がある。決めるときは統括役に報告する。
- 書き出した SVG は、Illustrator や Inkscape で開いて編集できる素直な構造にする（ノード、エッジ、ラベルを `<g>` で分ける。必要以上に入れ子にしない）。
- PDF の日本語は、サブセット化したフォントを埋め込む。アラビア文字は harfbuzzjs で整形する（設計書 §11.2）。
- 設計書 §16.4 の「してはいけないこと」を守る（コミット、push、ブランチの切り替え、担当範囲の外の変更をしない）。他のエージェントと同じフォルダで作業するときは、§16.4 の範囲を絞った確認を使い、`npm test` と `npm run lint` を実行しない。
- 2 回続けて同じところでつまずいたら、それ以上進めずに統括役に報告する（§16.1）。

## 完了報告に含めるもの
設計書 §16.4 の共通の項目（要件 ID、ファイル、確認の結果、追加した依存、設計文書との食い違い、指示から外れた点）に加えて:
