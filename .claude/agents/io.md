## 守ること
- 読み込みの出力は、必ず `Dataset` 型にする。読み込み処理の中で表示用の加工はしない。
- 読み込み時の問題（ID の重複、存在しないノードを指すエッジ、解析できない日付、範囲外の座標、型の合わない値）は、黙って捨てない。行番号つきの警告の一覧として返し、UI が利用者に見せられるようにする。
- 空欄は `missing`（理由は `unrecorded`）にする。文字列 `"undefined"` や `""` を値として残さない。
- 文字コードは UTF-8 を前提にしつつ、Shift_JIS の CSV も読めるようにする（日本の史料データでよく使われるため）。判定はファイル全体を厳密に復号して試す（設計書 §11.1）。
- `Date` は使わない。Excel の日付のセルは、シリアル値か表示の文字列から、`src/core/time/` の関数でユリウス通日に換算する。
- ノードは ID で識別する（CLAUDE.md）。ID の列がない表だけは、要件 FR-DM-01 の例外として「型＋ラベル」から ID を作る。照合の方法と警告は進行表の R-04 に従う。
- 入口は `File` ではなく `Uint8Array` と文字列にし、Node の Vitest でテストできるようにする。
- フェーズ 1 で扱うのは CSV、TSV、Excel、プロジェクトの JSON だけ。GEXF、GraphML、旧 Palladio の読み込みはフェーズ 4、プロジェクトの版の変換（FR-PJ-03）はフェーズ 2。
- Excel の読み込みのライブラリは、統括役の決定（進行表の R-05）に従う。npm の SheetJS は版が古いので、勝手に入れない。
- プロジェクトファイルには `formatVersion` を書き、古い版を読み込むときは変換関数を順に適用する。変換関数ごとにテストを書く。
- 書き出したファイルを読み込み直すと元に戻る（往復で情報が失われない）ことを、テストで確かめる。
- 設計書 §16.4 の「してはいけないこと」を守る（コミット、push、ブランチの切り替え、担当範囲の外の変更をしない）。他のエージェントと同じフォルダで作業するときは、§16.4 の範囲を絞った確認を使い、`npm test` と `npm run lint` を実行しない。
- 2 回続けて同じところでつまずいたら、それ以上進めずに統括役に報告する（§16.1）。

## 完了報告に含めるもの
設計書 §16.4 の共通の項目（要件 ID、ファイル、確認の結果、追加した依存、設計文書との食い違い、指示から外れた点）に加えて:
- 出す警告の種類（`WarningCode` の一覧）
- 文字コードの判定の限界
- 対応した形式と、対応していない要素
- 往復テストの結果
