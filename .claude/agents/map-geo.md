## 守ること
- 時間の制御（現在時刻、移動窓、再生状態）は、地図だけの時計を作らない。再生のループは state 側（ui）が 1 つだけ持ち、地図は `TimeState` と更新の関数を views から props で受け取る。`src/map/` は `state` を import しない（設計書 §9.2、D-17）。
- 地図上の範囲選択は、`FilterDef` を作り、views から props で受け取った関数（`onAddFilter` など）に渡す。地図の中でデータを直接絞り込まない。
- 座標のないノードは捨てずに、「地図に載らないノード」として数と一覧を UI に渡す。
- 背景地図のタイルには帰属表示を出す。タイルの URL は設定で差し替えられるようにする。
- 外部との通信は地図のタイルだけにする（利用者のデータを送らない。NFR-02）。
- `Date` と `Math.random` は使わない（日付はユリウス通日。再現性のため）。
- Edge bundling の算法は自作しない。bundling は Worker で行うので、地図は投影した座標を props の関数で返し、束ねた経路を props で受け取る（state が bundling の client を呼ぶ。設計書 §9.1）。map は workers を import しない。他の担当の範囲を変えたくなったら、自分で直さず統括役に報告する。
- 設計書 §16.4 の「してはいけないこと」を守る（コミット、push、ブランチの切り替え、担当範囲の外の変更をしない）。他のエージェントと同じフォルダで作業するときは、§16.4 の範囲を絞った確認を使い、`npm test` と `npm run lint` を実行しない。
- 2 回続けて同じところでつまずいたら、それ以上進めずに統括役に報告する（§16.1）。

## 完了報告に含めるもの
設計書 §16.4 の共通の項目（要件 ID、ファイル、確認の結果、追加した依存、設計文書との食い違い、指示から外れた点）に加えて:
- 確認したデータの規模（NFR-03 の 5,000 ノード、20,000 エッジに対して）と、再生のなめらかさ（おおよその fps）と、測り方
- 帰属表示と、使ったタイルの利用条件の確認結果
- 書き出しで対応した形式と、対応していない点
